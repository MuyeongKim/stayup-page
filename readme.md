# Stay Up World

전북소방 드론전문팀 **Stay-Up**과 드론축구팀 **FireHawks**의 소개, 활동 기록, 공개 프로그램을 안내하는 웹사이트입니다.

- 운영 주소: [www.stayup-ai.com](https://www.stayup-ai.com/)
- 공개 화면: 포털 홈, Stay-Up 소개, FireHawks 소개, 전체 활동 기록
- 관리자: [활동·출전 일정 관리](https://www.stayup-ai.com/admin/)
- 구성: HTML/CSS/JavaScript, Node.js 빌드, Vercel Functions, GitHub 기반 콘텐츠 관리

## 실행과 검증

Node.js 20.9.0 이상이 필요합니다. 설치 시 저장소의 `package-lock.json`을 사용합니다.

```sh
npm ci
npm run check
npm run build
python3 -m http.server 4173 --bind 127.0.0.1 --directory dist
```

브라우저에서 `http://127.0.0.1:4173/`을 엽니다. 배포되는 화면은 `dist/`이므로, 기본 HTML에 포함된 활동 기록까지 확인하려면 **빌드 결과를 실행**해야 합니다.

일반 정적 서버는 `/api/auth`, `/api/callback`, `/api/visitors`를 실행하지 않습니다. 이 환경에서 방문 현황이 `—`로 표시되는 것은 정상입니다. OAuth와 Redis 연결 설정은 [.env.example](.env.example), [ADMIN_SETUP.md](ADMIN_SETUP.md)를 참고하세요. 실제 비밀값은 저장소에 넣지 않습니다.

## 콘텐츠 관리

| 대상 | 데이터 | 공개 화면 |
| --- | --- | --- |
| Stay-Up 활동 | `data/stayup-activities.json` | 홈, Stay-Up 소개, 전체 활동 |
| FireHawks 활동 | `data/firehawks-activities.json` | 홈, FireHawks 소개, 전체 활동 |
| FireHawks 출전 일정 | `data/firehawks-schedules.json` | FireHawks 소개 |

관리자는 GitHub 저장소 쓰기 권한이 있는 계정으로 로그인합니다. 활동 또는 일정을 저장하면 GitHub 커밋이 생성됩니다. **저장 완료와 운영 사이트 반영 완료는 다릅니다.** Vercel 배포가 끝난 뒤 공개 화면을 확인하세요.

사진은 관리자에서 WebP로 변환하고 EXIF·GPS 정보를 제거합니다. 빌드에서는 업로드 사진을 다시 검증·최적화하며, 원본 업로드 디렉터리를 `dist/`에 복사하지 않습니다.

`published: false`인 활동과 일정은 배포용 JSON과 기본 HTML에서 제외됩니다. 다만 이 저장소는 공개 저장소이므로 **숨김은 보안상 비공개가 아닙니다.** 원본과 Git 이력에는 기록이 남을 수 있습니다.

날짜는 `YYYY`, `YYYY-MM`, `YYYY-MM-DD`를 지원합니다. 종료일과 비교할 때 시작일은 해당 기간의 시작, 종료일은 해당 기간의 끝으로 해석합니다. `displayDate`가 있으면 사용자가 지정한 표시 날짜를 우선합니다. 활동 설명의 줄바꿈은 공개 화면에서도 유지합니다.

## 2026-09-05 변경사항

코드리뷰에서 확인한 저장 안정성, 사용자 동선, 모바일 화면 문제를 보완했습니다.

### 관리자 저장과 편집

- 같은 활동·일정을 다른 관리자가 수정한 경우, 최신 목록만 가져온 뒤 낡은 폼으로 덮어쓰던 문제를 보완했습니다. 작성 중인 입력을 보존하고 충돌 내용을 확인·해결한 뒤 저장하도록 했습니다.
- 다른 항목만 변경된 경우에는 최신 목록을 기준으로 작성 중인 내용을 다시 저장할 수 있도록 했습니다.
- 사진 변환 중 편집창을 닫았다가 다시 열어도 저장 버튼 상태가 정상 복구되도록 했습니다.
- 작은 화면에서 사진 선택 입력의 고유 너비 때문에 날짜·제목 입력란이 잘리던 문제를 수정했습니다.
- 공개 여부에 따라 저장 버튼의 문구를 구분해, 숨긴 내용을 게시하는 것으로 오해하지 않도록 했습니다.
- Vercel 기본 주소나 Preview 주소로 관리자에 들어오면 `www.stayup-ai.com/admin/`으로 이동하도록 구성했습니다. 공개 Preview 화면은 계속 확인할 수 있고, 로컬 개발 주소는 리디렉션에서 제외됩니다.

### 활동 조회와 장애 복구

- 각 데이터 요청에 8초 제한시간을 적용하고, 먼저 확보한 팀의 기록부터 표시합니다.
- 일부 요청이 실패하면 확보한 기록을 유지하고 실패한 부분을 다시 불러올 수 있습니다.
- 홈의 활동 카드가 팀·연도 목록만 열던 동작을 개선했습니다. 이제 해당 활동의 고유 주소로 이동하고 기록을 강조합니다.
- 전체 활동 카드에 개별 활동 링크를 제공하므로 특정 기록을 다시 찾거나 주소를 공유할 수 있습니다.
- 공개 페이지의 활동 검증을 공용 로직으로 맞췄습니다. 관리자에서 허용한 월 단위 시작일과 일 단위 종료일 조합이 전체 활동 목록에서 제외되던 문제를 수정했습니다.
- 빌드 시 공개 활동과 출전 일정을 HTML에 포함합니다. JavaScript가 꺼져 있거나 이후 데이터 요청이 실패해도 마지막 배포 시점의 기록은 읽을 수 있습니다. 팀·연도 필터와 일정 진행 상태 갱신에는 JavaScript가 필요합니다.
- 섹션 바로가기의 주소·키보드 초점 처리를 보완해, 이동 후 Tab을 눌렀을 때 상단으로 되돌아가던 문제를 수정했습니다.

### 화면과 안내

- 전체 활동 페이지의 반복되는 큰 소개 영역을 줄여 필터와 기록이 더 빨리 나타나도록 했습니다.
- 활동 날짜는 14px, 분류 표시는 13px 이상으로 조정했습니다.
- 헤더의 공통 메뉴를 `포털 홈 · Stay-Up · FireHawks · 전체 활동` 순서로 통일했습니다. 기술 서비스는 홈의 서비스 영역과 하단 메뉴에서 확인할 수 있습니다.
- FireHawks ‘팀 이야기’ 사진에 원본 비율을 적용했습니다. 모바일에서도 높이가 1018px로 고정되어 단체 사진 양옆이 잘리던 문제를 수정했습니다.
- AI 객체탐지 링크의 안내를 ‘웹에서 직접 체험’에서 실제 제공 방식인 ‘프로그램 소개·다운로드 / Windows 배포본 제공’으로 변경했습니다.
- JavaScript가 꺼진 경우에도 모바일 팀 메뉴를 사용할 수 있도록 기본 표시를 제공합니다.

### 빌드와 회귀 검증

- Sharp를 보안 수정 버전 `0.35.4`로 갱신했습니다. Sharp는 이미지 빌드에 사용하며 공개 API 요청을 처리하지 않습니다.
- 관리자 충돌 복구와 사진 변환 취소에 대한 모의 회귀 검증을 추가했습니다.
- 데이터 요청 제한시간·부분 응답·날짜 검증·활동 바로가기·키보드 이동에 대한 회귀 검증을 추가했습니다.
- 배포 결과의 기본 활동 카드, 고유 주소, HTML 이스케이프, 숨김 제외, 서울 시간 기준 일정 선택을 검증합니다.

## 변경 후 확인할 사용자 흐름

1. 홈 → 최근 활동 카드 → 선택한 기록으로 이동 → 개별 주소로 다시 열기
2. 전체 활동 → 팀·연도 선택 → 새로고침 후 조건 유지
3. 데이터 요청 하나가 지연·실패해도 다른 기록 읽기 → 실패한 요청 다시 불러오기
4. JavaScript를 끈 상태에서 홈·팀 소개·전체 활동의 기본 기록 읽기
5. 키보드로 ‘현장 활동 보기’ 실행 → Tab으로 목적지 안의 다음 링크 이동
6. 관리자에서 사진 변환 중 취소 → 다시 편집 → 저장 버튼 활성 상태 확인
7. 두 관리자의 동시 편집 → 충돌 내용 확인 → 최신 변경을 보존해 저장
8. 320/375/520/760/980/1440px에서 메뉴·카드·입력창이 잘리지 않는지 확인

## 검증 범위와 운영 반영

2026-09-05 로컬 검증에서 `npm run build`, 관리자·공개 화면 회귀 검사, `git diff --check`를 통과했으며 `npm audit --omit=dev` 결과는 취약점 0건입니다.

| 비교 항목 | 수정 전 | 수정 후 |
| --- | --- | --- |
| 375×900px 전체 활동의 첫 카드 위치 | 페이지 상단에서 약 1,060px | 약 616px |
| 375px FireHawks 팀 이야기 사진 | 343×1018px, 양옆 잘림 | 약 343×274px, 원본 비율 |
| 320px 관리자 편집 영역 | 표시 282px / 내용 367px | 표시·내용 모두 282px |
| JavaScript 없는 전체 활동 | 기록 0건, 로딩 안내 | 기본 기록 24건, 로딩 없음 |
| 한 팀 요청이 제한시간을 넘긴 경우 | 전체 응답 대기 | 기본 기록 유지, 실패한 팀만 재시도 |
| 섹션 이동 후 Tab | 상단의 다른 버튼으로 복귀 | 활동 영역의 다음 링크로 이동 |

공개 화면 네 곳은 320/375/520/760/980/1440px에서 가로 넘침과 JavaScript 실행 예외가 없음을 확인했습니다. 기록 수와 화면 위치는 이 검증 시점의 콘텐츠·브라우저 기준입니다.

관리자 회귀 검증은 모의 GitHub 응답을 사용하며 실제 운영 기록을 변경하지 않습니다. 정적 브라우저 검증만으로 실제 GitHub OAuth 승인, 운영 저장, Vercel 배포 성공까지 보증하지 않습니다.

운영 반영 시에는 원격 `master`의 새 CMS 커밋을 먼저 확인하고, 이번 변경과 합친 뒤 빌드를 다시 검증해야 합니다. 배포 후에는 관리자 주소 이동, 공개 활동 조회, 방문 현황 API와 화면을 별도로 확인합니다.

## 주요 파일

| 경로 | 역할 |
| --- | --- |
| `index.html`, `stayup/`, `firehawks/`, `activities/` | 공개 화면 |
| `css/` | 팀별 화면과 공통 조작 요소 |
| `js/activity-data.js` | 공용 활동 검증과 데이터 요청 |
| `js/activities.js` | 필터, 부분 응답, 활동 바로가기 |

| `api/`, `lib/` | OAuth와 익명 방문 현황 |
| `scripts/build.mjs` | 정적 파일 복사와 사진 최적화 |
| `scripts/render-static-content.mjs` | 기본 활동·일정 HTML 생성 |
| `scripts/check-dist.mjs` | 배포 결과 검증 |

방문 현황은 익명 브라우저 기준의 추정치이며 실제 인원 수가 아닙니다. API 장애 시 숫자를 임의로 표시하지 않고 `—`를 표시합니다.
